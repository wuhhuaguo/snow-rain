# 写作特征与迁移规则

这里的“稳定”表示在本次已读语料中多次出现，不代表是作者独有特征或已做统计学归因。来源简称见 [evidence-map.md](evidence-map.md)。优先采用 GBM、PPO、PPD、PromptPilot 的论证参照；对当前课题不适用的技术形式不迁移。

## 1. 先把实际困难变成一个可操作的问题

**观察，较高置信。** GBM 从 GBM 分割与标注困难收束到一张参考图引导的自动提示。PPO 从 SAM 对提示的依赖收束到点分布在两个空间中的要求。PPD 从初始提示中的错误、冗余及训练环境限制转向反馈驱动的攻防优化。PromptPilot 再明确语义一致性、空间覆盖与贡献分配之间的冲突。

它们不只是“背景—不足—提出网络”，而是先回答：**我们究竟应该优化什么，为什么原来的操作方式无法把它优化好？**

**迁移。** 写引言时，先找失败现象，再写产生失败的机制或假设，最后提出设计要求。例如用户做剪枝：不能直接把“参数冗余”跳接到“双分支蒸馏”；要说明压缩过程中哪种知识受损、现有恢复目标为何无法约束它，才有理由引入相应机制。这个例子是迁移建议，不是刘雪宇发表过该剪枝方法。

## 2. 把贡献写成“问题的重新表述 + 可运行的解决机制”

**观察，较高置信。** PPO 把提示优化转成图中的策略学习。PPD 用攻击者制造干扰、由防御者学习抑制，强调训练时的对抗与推理时的单防御者。PromptPilot 把提示构造写成多个目标相互作用的序贯决策，交由专门 actor 与 manager 协调。

**迁移。** 强贡献句通常包含三件事：改变了什么问题表述、增加了什么可执行机制、这个机制使什么原先无法完成的操作成为可能。只有“新颖框架／多模块结合／性能较好”时，先检查用户材料是否真的存在更具体的技术主张。没有则忠实表述已有价值，不编造“范式”。

## 3. 用互补约束推动模块设计

**观察，较高置信但领域相关。** GBM 在特征空间验证对应关系、在物理空间控制提示。PPO 联合使用特征与位置距离。PromptPilot 明确二者的目标冲突并分工。DSAGL 则处理 bag-level 监督与 instance-level 学习间的不一致。

**迁移。** 找到本研究中真实存在的两个层级、条件或目标，它们为何不能被单一操作兼顾，再解释如何协调。可以是局部／整体、表示／输出、准确率／计算量，也可以只有一个关键目标。**双空间、双分支、teacher-student、manager 都是这些论文的具体解法，不是写作风格要求。**

## 4. 先总览，再沿信息流展开

**观察，较高置信。** GBM 的方法开头先给三个环节与参考／目标输入，再展开特征和提示；PPO 先说明矩阵、图环境、训练、推理；PPD 说明环境、攻防训练与仅防御者推理。PromptPilot 先给图环境、两个 actor、manager 的关系。

**迁移。** 方法开头用一段话让读者知道：输入是什么、在哪个表示中操作、核心机制按什么顺序作用、输出如何得到。随后小节应沿这个顺序走。符号与模块在第一次需要时解释。不要先写两页公式，最后才告诉读者它们服务于什么操作。

## 5. 解释每一步为何需要存在

**观察，较高置信。** GBM 的 backward matching 小节先说明仅前向对应会产生错误提示，再解释反向一致性筛选；后续空间采样围绕剩余错误和冗余展开。IFP 的结构一致性小节先指出同类不同结构相似度有差异，再给相应约束。

**迁移。** 模块段落按“上一环节仍有什么问题 → 本步处理哪个对象 → 具体怎么处理 → 输出供哪一步使用”写。不是每段都要四句，但这四项应能从上下文中找到。公式紧跟它定义的操作，别把实现细节全部包装成理论创新。

## 6. 提出可见的设计诉求，并用实验回应

**观察，较高置信。** PPO 用双空间消融与不同初始提示比较检验机制和通用性。PPD 的攻防消融展示性能被破坏与恢复，并考察不同 SAM 方法及运行效率。PromptPilot 安排性能比较、消融与即插即用研究。DSAGL 在不同实例规模／弱监督条件下做细化分析。

**迁移。** 每张结果表先指定要回答的问题。整体比较回答“是否有效”；消融回答“哪个机制起作用”；跨条件实验回答“在什么范围成立”；时间／计算结果回答“代价如何”。四种问题是可选证据种类，不强制每篇拥有相同数量的实验。

性能解释优先指向瓶颈对应条件：边界模糊、初始提示受扰、正实例稀少等。不得仅从相关结果断言因果机制已获证明。图像看起来更好，也不能单独证明统计显著或临床可用。

## 7. 显式衔接，但少写空泛修饰

**观察，中等置信。** 多篇使用表示转折、方案提出、细化操作与证据回扣的连接手段。短语本身属于常见学术英语，不能凭它们识别作者。PPO／PPD 常用主动的“we + 操作”；PromptPilot 正式版也多用被动结构，因此不能规定全篇只用主动或只用被动。

**迁移表达功能，避免机械复述原句：**

| 功能 | 更有效的写法 | 无效替代 |
|---|---|---|
| 问题转折 | 说明一种明确机制在某个条件下失败 | 每段重复 However 而没有新信息 |
| 引入方案 | 直接指出所处理的缺口与操作对象 | 只有 novel、effective、powerful |
| 展开机制 | 主语是实际模块，谓语是可复现操作 | 堆砌“协同、赋能、全面提升” |
| 解释结果 | 报告现象，再指出与哪个设计诉求一致 | 表格中每个数字重述一遍 |
| 界定能力 | 给条件、对象与所需监督 | 不加范围的 universal、any、robust |

可使用 define、construct、represent、generate、refine、align、coordinate、quantify 等具体动词，但每个动词都必须对应真实操作。修正语料中的语法、重复与模板残留。

具体句法、段落节奏、语态和标点实施见 [language-guide.md](language-guide.md)。无破折号、无冒号、少用括号插话等来自用户成稿偏好，优先于对原文标点的模仿。

## 8. 贡献列表要对应不同价值层级

**观察。** PPO、PPD、IFP 常见三项，PromptPilot 是四项；GBM 没有必须保留的同款列表。贡献数量并不固定。

**迁移。** 从用户真实贡献中选择互不重复的层级，例如“问题表述”“核心机制”“经验证实的能力”。若某条只是在换词重复另一条，应合并。实验验证可以构成一项经验性贡献，但“做了很多实验”本身不足以成为重要贡献。不要自动添加“首个”或“首次”。

## 9. 随体裁改变叙事重心

| 参照分支 | 已读来源 | 可迁移重点 | 不应据此推出 |
|---|---|---|---|
| 医学图像问题驱动 | GBM；MSA、Life 作合作论文补充 | 任务对象与标注负担，局部到整体的处理链，诊断／测量的潜在用途 | 每篇都先介绍疾病；模型实验已证明临床部署有效 |
| 通用基础模型方法 | PPO、PPD、PromptPilot、IFP | 提示瓶颈、优化表述、反馈与泛化，训练／推理边界 | 每篇都必须使用 SAM 或强化学习 |
| 长篇弱监督学习 | DSAGL | 任务与符号、层级监督、模块／损失、分层实验与讨论 | 所有方法都需要六章或单独 Discussion |
| 神经信号／跨模态合作论文 | D4PM、BI-Cap | 从干扰来源或模态鸿沟引出机制，分清互补信息来源 | 这些合作论文措辞均由刘雪宇执笔 |
| 临床合作 | RA | 结构式摘要，研究对象、干预、终点与统计结果 | 算法贡献列表适用于临床研究 |

综述分支尚无全文依据。标题反映主题，不能用来重建其综述内部逻辑。

## 10. 风格迁移的停点

当继续追求“像”会改变事实、夸大创新、编造基线、抹去不利结果、复制原文或强改技术路线时，停止该项风格迁移，保留内容正确性。局限应具体、与证据相称；没有必要把论文写成缺陷清单，也不删除目标期刊需要的讨论。
